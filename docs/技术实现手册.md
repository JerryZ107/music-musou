## 3. 代码架构（数据怎么流）

```text
音频播放 (demo_music.play_music_profile)
    → music_timeline_ms（减 latency，对齐扬声器）
    → BeatGridClock（beat_times_ms + loop_ms）
    → hud_in_zone / judgment_for_combat（卡拍？）
    → 普攻/滑步伤害倍率 + 大招充能 +1

输入 (WASD / Enter / Shift / Space)
    → 移动、圆形/半圆/子弹/激光判定
    → 敌人 AI、接触伤害、胜负
    → visuals 绘制世界 + 节拍 HUD
```

**核心类**

- `MusicProfile`：某模板对应的 `wav_name`、`beat_times_ms`、`loop_ms`、`bpm_label`。
- `BeatGridClock`（`prototype.py`）：用预烘焙拍点做 **二元** 卡拍（无 Perfect/Good）。
- `ProtagonistTemplate`：1 圆斩 / 2 半圆+Buff 大招 / 3 锁敌弹+分身大招。

## 4. 设计 canon vs 当前 Demo

| 维度 | 完整版（文档 + ADR） | 当前像素 Demo |
|------|----------------------|---------------|
| 选曲 Build | Track + Allocation + **Run 内不换 Track** | **无加点**；用 1/2/3 **Hero 机制**；**canon：一 Run 一曲**（ADR 0010） |
| 充能 | **Combat Hit** 才 `Energy Grant`；Beat-On **2× Grant**；有 **Energy Hit Cap** | **卡拍判定成功即 +1 充能**（与是否命中敌人解耦），满 **5** 次放大招 |
| 伤害 | Beat-On Hit **2×** vs Basic | 卡拍攻击 **2×** 伤害（与 canon 一致方向） |
| Minion TTK | Basic **2 击**、Beat-On **1 击**（HP=2, 伤=1/2） | `MINION_HP=2`，`BASIC_ATTACK_DAMAGE=1`，卡拍倍率 2 |
| Beat Map | 每 Track 预烘焙 | 1/3 号规整 BPM 网格；2 号按《欢乐颂》旋律起音列表 |
| BPM 检测 | **不做**（v0 明确边界） | 同左 |

上线 MVP 前若要对齐 canon：充能改回「仅 Combat Hit Grant」，并接入 Cap 轴（见 ADR 0002、0003）。

## 5. 节奏与判定（实现要点）

### 5.1 时间轴

- `music_timeline_ms(fallback_ms, latency_ms)`：`get_pos() - latency`，默认 latency **130ms**（`DEFAULT_AUDIO_LATENCY_MS`）。
- 游戏中 **`[` / `]`** 微调 latency；命令行 `--beat-latency=`。

### 5.2 拍点表

- 存在 `MusicProfile.beat_times_ms`（单位 ms，相对 **loop 起点**）。
- `loop_ms` 为循环长度；`t_loop = timeline % loop_ms`。
- 最近拍距离 + **相位** `beat_phase01` 驱动 HUD 亮区宽度（与 `beat_window_ms` 成比例）。

### 5.3 判定窗

| 项 | 代码常量 | 说明 |
|----|----------|------|
| 总窗宽 | `BEAT_WINDOW_MS = 320` | 策划案 §9.1 曾写 280，**以代码为准** |
| 战斗判定 | `judgment_for_combat` | 当前帧在亮区，或上一帧 HUD 可拍 + **55ms** 宽限 |
| 二元 | ADR 0007 | 窗内 = 卡拍收益；窗外 = Basic，无分档 |

### 5.4 三模板 BGM（`demo_music.py`）

| 模板 | WAV | 节拍来源 |
|------|-----|----------|
| 1 | `musou_loop.wav` | 120 BPM × 8 小节规整 4/4 |
| 2 | `musou_loop_t2.wav` | 84 BPM，旋律起音时间列表 |
| 3 | `musou_loop_t3.wav` | 140 BPM × 8 小节规整 4/4 |

WAV 可由生成器写入 `demo/assets/`；`.wav.gen` 第一行 `generator_id` 用于是否需要重生成。

**换用户音频**：替换 assets + 更新 `PROFILE_TEMPLATE3` 的 `beat_times_ms` / `loop_ms`（离线分析或手标），**不要**依赖运行时 BPM 分析。

## 6. 战斗与三主角模板

| | 1 号 | 2 号 | 3 号 |
|---|------|------|------|
| HP | 10 | **8** | **5** |
| 普攻 | 全圆 r=2 | 半圆 r=3，**锁最近敌** | 1 格子弹，锁敌，射程 5，速度 2×移速，伤害 ×0.5 |
| 普攻/滑步 CD | 280 / 360 ms | **+100ms** | 同 1 号 |
| 卡拍伤害 | 2× | 2×（Buff 期间普攻 +1） | 2×（穿透等见代码） |
| 大招 | 圆 r=4，伤 3 | 5s：半径+1、伤+1 | **分身** 5 HP、嘲讽、与主角同步 Enter 攻击 |

共享：`SLIDE` 3 格 / 110ms；接触伤 1 / 0.5s i-frame；滑步中免接触伤。

大地图：**48** 杂兵 + **4** Boss；训练场在 `tutorial` 流程内（见 `prototype` 状态机 `RunState`）。

## 7. 数值基准（Demo 常数）

实现位置：`demo/prototype.py` 文件头 + `player_max_hp()`。

| 常量 | 值 | 设计含义 |
|------|-----|----------|
| `MINION_HP` / `BOSS_HP` | 2 / 12 | Minion：不卡拍 2 刀、卡拍 1 刀 |
| `BASIC_ATTACK_DAMAGE` | 1 | Basic Hit |
| 卡拍倍率 | 2 | 对齐 Beat-On 2×（ADR 0008） |
| `ULTIMATE_BEAT_CHARGES` | 5 | Demo 线性充能条 |
| `ULTIMATE_DAMAGE` | 3 | 1 号大招 |
| `BEAT_WINDOW_MS` | 320 | Judgment Window 总宽 |
| `DEFAULT_AUDIO_LATENCY_MS` | 130 | 默认音频补偿 |

Boss 只看 **Health Pool** 扣血，不适用「两刀杂兵」规则。
